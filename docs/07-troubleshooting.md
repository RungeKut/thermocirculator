Актуально на 16.09.2026. Каждая запись: симптом → причина → проверка → решение.

## П-01. Сборка обрывается: «ARM-Compiler ... is not available»

**Симптом**

```
*** Target 'STM32L071CBT6' uses ARM-Compiler 'Default Compiler Version 5'
    which is not available.
*** Rebuild aborted.
```

Затрагивает **оба** ST-проекта: у них в `.uvprojx` стоит `<uAC6>0</uAC6>`.

**Причина**

Проекты требуют Arm Compiler 5, а в установленной MDK 5.39 его нет —
каталог `C:\Keil_v5\ARM\ARMCC` отсутствует, остался только `ARMCLANG`
(Arm Compiler 6.21). Компилятор пропал при переустановке MDK.

**Это не ошибка в коде.** До переустановки обе прошивки собирались
успешно: L072 — 02.03.2025 (0 ошибок, 0 предупреждений), L071 — январь 2026
(слинкована прошивка 26.90 КБ).

**Проверка**

```bash
ls /c/Keil_v5/ARM/          # есть ли ARMCC рядом с ARMCLANG
head -1 <проект>/MDK-ARM/<таргет>/*.map   # чем собиралось в прошлый раз
```

**Решение**

Установить Arm Compiler 5.06u7 — [03-environment.md](03-environment.md), шаг 2.
Либо перевести проекты на ArmClang, но **не одновременно** с правкой
конфигурации периферии: иначе непонятно, что сломалось. Варианты и
рекомендация — [adr/0001-toolchain.md](adr/0001-toolchain.md).

## П-02. L071 собирается, но показывает 0 °C и не греет

**Симптом**

Прошивка линкуется без ошибок, дисплей работает, но все температуры равны
нулю, нагрев не включается.

**Причина**

При перегенерации проекта в CubeMX потеряна конфигурация АЦП: остались
только каналы `ADC_CHANNEL_0/1/2`, а `ADC_CHANNEL_TEMPSENSOR` и
`ADC_CHANNEL_VREFINT` исчезли (в `.ioc` L072 они присутствуют как
`VP_ADC_TempSens_Input` и `VP_ADC_Vref_Input`, в `.ioc` L071 их нет).

Код выбирает канал напрямую через `ADC1->CHSELR`, поэтому каналы 16 и 17
выберутся. Но биты включения внутренних источников (`ADC->CCR`: `TSEN`,
`VREFEN`) выставляет `HAL_ADC_ConfigChannel()` при инициализации — и теперь
их не выставляет никто. Дальше по цепочке:

- `sense[4]` (VREFINT) = 0, а он служит **делителем**;
- `senseAdcRef = (sense[4]/4095)*3.3` = 0;
- все три температуры = `calc_temperature(...) * senseAdcRef/12` = **0**;
- `senseTempMCU` = деление на ноль.

**Проверка**

```bash
grep -c "ADC_CHANNEL_TEMPSENSOR\|ADC_CHANNEL_VREFINT" STM32L071CBT6/Core/Src/adc.c
# 0 — конфигурация потеряна; 2 — на месте
```

В отладчике: `sense[4]` должен быть около 1500…1700 при исправном VREFINT.

**Решение**

Вернуть в CubeMX и перегенерировать:

| Что | Значение | Где потеряно |
|---|---|---|
| Канал `TEMPSENSOR` | включить | `Core/Src/adc.c` |
| Канал `VREFINT` | включить | `Core/Src/adc.c` |
| `ClockPrescaler` | `SYNC_PCLK_DIV4` | стало `DIV2` |
| `SamplingTime` | не менее 12.5 тактов | стало 1.5 такта |
| Прерывание `RTC_IRQn` + `sAlarm` | включить | `Core/Src/rtc.c`, `stm32l0xx_it.c` |
| PB12, PB13, PB6, PB7 | вход с подтяжкой вниз | `Core/Src/gpio.c` |
| PB15 | вход | `Core/Src/gpio.c` |
| `HAL_RCCEx_EnableLSECSS()` | вызвать | `Core/Src/main.c` |

Время выборки 1.5 такта мало для NTC через 10 кОм в любом случае: ёмкость
устройства выборки-хранения не успевает зарядиться, показания будут
занижены и шумны.

## П-03. Правки в `Core/` исчезают после CubeMX

**Симптом**

После перегенерации проект снова ведёт себя как до исправлений.

**Причина**

CubeMX сохраняет только то, что находится между маркерами
`/* USER CODE BEGIN ... */` и `/* USER CODE END ... */`. Всё остальное
перезаписывается из `.ioc`.

В проекте уже есть след этой проблемы: в `.ioc` L072 записано
`ADC.SamplingTime=ADC_SAMPLETIME_160CYCLES_5`, а в сгенерированном
`Core/Src/adc.c` стоит `ADC_SAMPLETIME_12CYCLES_5` — вне блоков `USER CODE`.
То есть рабочий код L072 правился руками помимо CubeMX и **не совпадает со
своим же `.ioc`**. Любая перегенерация L072 эту правку потеряет.

**Проверка**

Перед перегенерацией:

```bash
grep -n "SamplingTime" <таргет>/Core/Src/adc.c <таргет>/*.ioc
```

Значения должны совпадать. Если нет — в коде есть ручная правка, которая
будет потеряна.

**Решение**

Правило: **настройки периферии меняются только через `.ioc`.** Если значение
в CubeMX недоступно — правка идёт в блок `USER CODE`, а не поверх
сгенерированного кода. См. [08-rules.md](08-rules.md).

## П-04. uVision не видит целевое устройство

**Симптом**

Устройство не выбирается в настройках таргета, либо не разрешаются исходники
SPL в проекте GD32.

**Причина**

Не установлены пакеты поддержки устройств. Каталог `C:\Keil_v5\ARM\PACK`
содержит только `.Download` и `.Web`; в кэше лежат лишь базовые пакеты из
установщика MDK (CMSIS, MDK-Middleware) от 01.12.2023.

Для GD32 это критично: проект `keil/` подключает SPL через механизм RTE из
`keil/RTE/Device/GD32E103C8/`, и эти файлы приходят из пакета.

**Проверка**

```bash
ls /c/Keil_v5/ARM/PACK/
```

Должны быть каталоги `Keil/STM32L0xx_DFP/2.2.0` и
`GigaDevice/GD32E10x_DFP/1.3.0`.

**Решение**

Установить пакеты из офлайн-комплекта — [03-environment.md](03-environment.md),
шаг 3. Версии зафиксированы в `.uvprojx`, ставить нужно именно их.

## П-05. Отладчик не соединяется с GD32

**Симптом**

ST-Link, перепрошитый в J-Link, не видит GD32E103.

**Причина**

Зафиксированный опыт проекта: связка с GigaDevice не заработала.
Перепрошивка китайского ST-Link в J-Link сама по себе удалась (сначала
накатывается обычная прошивка STM32 + VCP), но с GD32 соединения получить
не удалось.

**Решение**

Использовать отдельный J-Link. Артефакты прошлых попыток —
`keil/JLinkLog.txt`, `keil/JLinkSettings.ini`.

## П-06. На GD32 не выводится на дисплей после инициализации таймера

**Симптом**

Дисплей и индикатор ведут себя непредсказуемо после вызова `TIM1_Init()`.

**Причина**

`TIM1_Init()` в `keil/Core/Src/tim.c` переводит в режим альтернативной
функции пины **PA15, PB3, PB10, PB11** — то есть `SPEAKER`, `DISP_DB3`,
`DISP_DB2` и `LED_R`. Для отладки ШИМ это допустимо, но конфликтует с
дисплеем.

**Решение**

Оставить под таймер только пин `SPEAKER`; остальные вернуть в режим выхода.
Задача входит в портирование, см. [06-porting.md](06-porting.md).

## Диагностические приёмы

**Чем собиралась прошивка в прошлый раз**

```bash
head -1 <проект>/MDK-ARM/<таргет>/*.map
```

**Полный ли линк** — есть ли в сборке прикладные модули:

```bash
grep -c "UserInterfaceExecuter\|TempMeasExecuter\|HeaterExecuter" *.map
```

**Размер прошивки** — сверить с эталоном в [04-build-and-flash.md](04-build-and-flash.md):

```bash
grep -i "Total ROM Size" *.map
```

**Расхождение кода и `.ioc`** — см. П-03.
