# ADR-0002. Общая кодовая база для трёх таргетов

- **Дата:** 16.09.2026
- **Статус:** принято
- **Контекст:** [01-overview.md](../01-overview.md), [06-porting.md](../06-porting.md)

## Проблема

Прикладной код (интерфейс, ПИД, измерение температуры, работа с памятью)
существует в трёх копиях. Сейчас `User/` в L071 и L072 совпадает побайтно, а
в GD32 лежит их закомментированная версия. Любое изменение по новому ТЗ
пришлось бы вносить трижды, а расхождения копий обнаруживались бы только
на железе.

## Решение

Разделить код на переносимую часть и слой адаптации к железу.

```
app/                 логика: UI, автомат состояний, ПИД, NTC-таблица, LCD1602
  ports.h            единственный контракт с железом
port/stm32l0/        реализация для L071 и L072 (одна на оба)
port/gd32e10x/       реализация для GD32E103
targets/
  stm32l072/         проект сборки + сгенерированный CubeMX Core
  stm32l071/
  gd32e103/
```

Правило: **в `app/` нет ни одного вызова HAL или SPL.**

## Почему это реалистично

Прикладной код обращается к железу всего **12 различающимися операциями**
(подсчёт по `User/Src/*.c` эталонного L072):

| Операция | Вхождений |
|---|---|
| `HAL_Delay` | 20 (+29 в LCD1602) |
| `HAL_GetTick` | 14 |
| `HAL_GPIO_WritePin` | 8 |
| `HAL_TIM_PWM_Start` / `Stop` | 9 |
| чтение `GPIOx->IDR` | 3 |
| работа с АЦП | 9 |
| работа с флеш-памятью | 4 |
| `TIM2->ARR` / `CCR1` | 2 |

Всё остальное в ~1100 строках — арифметика и логика без обращения к железу.
Контракт укладывается примерно в 15 функций:

```c
uint32_t port_tick_ms(void);
void     port_delay_ms(uint32_t ms);

void     port_pin_write(port_pin_t pin, bool state);
uint8_t  port_keys_read(void);
uint8_t  port_levels_read(void);

void     port_adc_select(port_adc_ch_t ch);
void     port_adc_start(void);
uint16_t port_adc_value(void);

void     port_pwm_freq(uint32_t hz);
void     port_pwm_start(void);
void     port_pwm_stop(void);

uint32_t port_nvs_read(uint8_t idx);
void     port_nvs_write(uint8_t idx, uint32_t value);
void     port_nvs_erase(void);
```

## Что этот слой скрывает

| Различие | STM32L0 | GD32E10x |
|---|---|---|
| Выбор канала АЦП | регистр `CHSELR` | регулярная и вставленная группы |
| Запись в GPIO | `->BSRR` | `GPIO_BOP` / `GPIO_BC` |
| Страница флеша | 128 байт | 1 КБ |
| Объём флеша | 128 КБ | 64 КБ |
| Тактовая частота | 32 МГц | 72 МГц |

Последнее особенно важно: `SetSoundFreq()` содержит константу `32000000/f`,
которая молча даст неверную частоту на GD32. В слое абстракции частота
становится параметром порта, а не константой в прикладном коде.

## Порядок внедрения

1. Выделение делается **на эталонном L072**, где есть рабочая прошивка для
   сверки. Каждый шаг — рефакторинг без изменения поведения.
2. Затем к готовой структуре подключается L071 — он делит порт с L072 целиком.
3. Новое ТЗ вносится один раз в `app/`.
4. GD32 доделывается последним, против уже стабилизированного `app/`.

**Шаг 4 не может идти раньше шага 1.** Если сначала доделать GD32 в текущей
структуре, весь портированный код (LCD, флеш, АЦП, ПИД) придётся переписывать
под контракт заново.

## Дополнение от 16.09.2026: влияние нового ТЗ

Новое ТЗ получено — [09-requirements.md](../09-requirements.md). Ключевое для
этого решения: **новой периферии не появляется**, плата не меняется. Контракт
остаётся почти таким, как спроектирован; добавляются пять функций:

```c
void     port_cooler_pwm(uint8_t percent);   // ШИМ кулера, Ф-07
uint32_t port_rtc_now(void);                 // метки времени журнала, Ф-09
void     port_rtc_set(uint32_t seconds);
void     port_wdt_kick(void);                // сторожевой таймер, E-20/E-25
port_reset_cause_t port_reset_cause(void);   // причина сброса, E-20/E-21
```

Тройка функций звука заменяется на пару, где громкость — параметр
(Ф-11), поскольку регулировка выполняется скважностью того же ШИМ:

```c
void port_sound_tone(uint32_t hz, uint8_t volume);  // вместо port_pwm_freq/start
void port_sound_off(void);                          // вместо port_pwm_stop
```

Итого около 20 функций вместо 15. Риск «периферия, не предусмотренная
контрактом» снят.

Объём изменений по ТЗ подтверждает порядок работ: портировать GD32 в старой
структуре, а затем переделывать интерфейс — значит выбросить работу целиком.

## Последствия
- Три копии `User/` удаляются; история сохраняется в git.
- Расхождение в именовании кнопок (см. [02-hardware.md](../02-hardware.md))
  должно быть разрешено до выделения `app/`.
