## Диагностика текущей машины

### Проблема 1: отсутствует Arm Compiler 5

Оба ST-проекта содержат в `.uvprojx` настройку `<uAC6>0</uAC6>` — то есть
требуют компилятор версии 5. Их последние успешные сборки выполнены
**armcc 5.06 update 7** из `C:\Keil_v5\ARM\ARMCC\Bin`:

- L072 — 02.03.2025, 0 ошибок, 0 предупреждений;
- L071 — январь 2026, слинкована прошивка 26.90 КБ.

После переустановки MDK 5.39 каталог `C:\Keil_v5\ARM\ARMCC` отсутствует —
остался только `ARMCLANG`. Сборка обрывается на:

```
*** Target '...' uses ARM-Compiler 'Default Compiler Version 5' which is not available.
*** Rebuild aborted.
```

Это **не ошибка в коде**. Решение — см. [adr/0001-toolchain.md](adr/0001-toolchain.md).

### Проблема 2: пакеты поддержки устройств — устранено 17.09.2026

Пакетов устройств не было ни одного. Без них uVision не разрешает целевое
устройство, а для GD32 дополнительно нет исходников SPL: проект `keil/`
подключает их через механизм RTE из `keil/RTE/Device/GD32E103C8/`.

Оба пакета установлены. После этого сборка L072 перестала жаловаться на
устройство и упирается только в отсутствие компилятора (проблема 1), а
проект GD32 дошёл до компиляции SPL.

> **Где на самом деле лежат пакеты.** MDK 5.39 хранит их в
> `%LOCALAPPDATA%\Arm\Packs\`, а не в `C:\Keil_v5\ARM\PACK\`.
> Второй каталог остался от старых версий; распаковка пакета туда
> не даёт ничего — uVision продолжает считать пакет неустановленным.

### Проблема 3: STM32CubeMX не установлен

Править `.ioc` и перегенерировать `Core/` нечем. Для восстановления L071
(шаг 2 плана) CubeMX обязателен.

Дистрибутивы трёх версий добавлены в комплект 17.09.2026. Установка требует
прав администратора и выполняется скриптом — см. шаг 4.

> Сама сборка CubeMX не требует: драйверы HAL вендорены в репозиторий
> (по 67 МБ на проект). CubeMX нужен только для изменения конфигурации
> периферии.

## Офлайн-развёртывание

Цель — возможность развернуть окружение на машине без интернета, повторяемо.

### Комплект

Всё необходимое собирается в каталог [`../tools/`](../tools/):

```
tools/
├── README.md          инструкция по пополнению и переносу комплекта
├── manifest.json      машиночитаемый перечень: версии, размеры, sha256, источники
├── verify.py          проверка комплектности и контрольных сумм
├── installers/        крупные инсталляторы (не под git)
├── packs/             пакеты поддержки устройств (.pack)
└── datasheets/        документация на компоненты
```

Комплект физически содержит все файлы, но под контроль версий попадают
только манифест, скрипт проверки и документация — крупные бинарники
исключены через `.gitignore`. Для переноса на другую машину копируется
каталог `tools/` целиком.

### Проверка комплекта

```bash
python tools/verify.py
```

Скрипт сверяет наличие и sha256 каждой позиции манифеста и печатает, чего
не хватает и откуда это взять.

### Порядок установки

Выполнять строго по порядку — последующие шаги зависят от предыдущих.

**Шаг 1. Keil MDK-ARM 5.39**

```
tools/installers/MDK539.EXE
```

Установить в `C:\Keil_v5`. Лицензирование — вне комплекта, см. ниже.

**Шаг 2. Arm Compiler 5.06 update 7**

Устанавливается отдельно, поверх MDK, в `C:\Keil_v5\ARM\ARMCC`.
Распространяется Arm как legacy-компонент и требует учётной записи Arm —
поэтому в комплект не входит и должен быть добавлен вручную один раз:

```
tools/installers/ARMCompiler5.06u7.exe
```

После установки прописать компилятор в uVision:
`Project → Manage → Project Items → Folders/Extensions → ARM Compiler`.

Альтернатива — перевести проекты на ArmClang 6 и не устанавливать AC5 вовсе.
Решение и его последствия — [adr/0001-toolchain.md](adr/0001-toolchain.md).

**Шаг 3. Пакеты поддержки устройств**

```
tools/packs/GigaDevice.GD32E10x_DFP.1.3.0.pack     ✅ в комплекте
tools/packs/Keil.STM32L0xx_DFP.2.2.0.pack          ✅ в комплекте (62 МБ)
```

Установка — двойным щелчком по `.pack`, запустится Pack Installer.

> `UV4.exe -pack <файл>` в версии 5.39 **молча ничего не делает** и
> возвращает код 0. Для автоматизации он непригоден.

Без графического интерфейса пакет ставится распаковкой вручную. Пакет —
обычный ZIP; его содержимое кладётся в
`%LOCALAPPDATA%\Arm\Packs\<Вендор>\<Имя>\<Версия>\`, а сам `.pack` вместе
с извлечённым `.pdsc` — в `%LOCALAPPDATA%\Arm\Packs\.Download\` под именем
`<Вендор>.<Имя>.<Версия>.pack`. Именно такую раскладку создаёт Pack Installer.

Проверка:

```bash
ls ~/AppData/Local/Arm/Packs/
```

Должны быть `Keil/STM32L0xx_DFP/2.2.0` и `GigaDevice/GD32E10x_DFP/1.3.0`.

> Версии зафиксированы: проекты ссылаются на `Keil.STM32L0xx_DFP.2.2.0` и
> `GigaDevice.GD32E10x_DFP.1.3.0` в `.uvprojx`. Установка другой версии
> приведёт к рассинхронизации. В комплекте лежит также
> `GigaDevice.GD32E10x_DFP.1.2.1.pack` — это историческая версия,
> **для сборки не используется**.

**Шаг 4. STM32CubeMX — три версии рядом**

```
tools/installers/cubemx/6.0.1/SetupSTM32CubeMX-6.0.1.exe       ✅ в комплекте
tools/installers/cubemx/6.2.0/SetupSTM32CubeMX-6.2.0-Win.exe   ✅ в комплекте
tools/installers/cubemx/6.4.0/SetupSTM32CubeMX-6.4.0-Win.exe   ✅ в комплекте
```

Версии ставятся **рядом**, каждая в свой подкаталог штатного пути:

```
C:\Program Files\STMicroelectronics\STM32Cube\STM32CubeMX\6.0.1
                                                         \6.2.0
                                                         \6.4.0
```

Они не конфликтуют. Держать несколько версий нужно потому, что проекты
создавались разными, а перегенерация чужой версией меняет содержимое `Core/`
сильнее, чем ожидается.

**Сначала понадобится Java.** Лаунчер инсталлятора CubeMX ищет JRE в реестре
(`HKLM\SOFTWARE\JavaSoft\Java Runtime Environment`) и без неё показывает окно
«This application requires a Java Runtime Environment 1.8.0_45 (64-bit)».
JRE, лежащая внутри STM32CubeIDE, в реестре не значится и **не подходит**.

Скрипт ставит Temurin JRE 8 сам, если зарегистрированной JRE нет. Ключевой
момент — набор компонентов MSI:

```
ADDLOCAL=FeatureMain,FeatureEnvironment,FeatureJarFileRunWith,FeatureJavaHome,FeatureOracleJavaSoft
```

Именно `FeatureOracleJavaSoft` создаёт совместимые ключи `JavaSoft` в реестре,
по которым лаунчер и находит Java. Без этого компонента установка JRE
проблему не решает. Пропустить установку JRE — ключ `-SkipJre`.

Установка всех трёх версий одной командой, **от имени администратора**:

```powershell
powershell -ExecutionPolicy Bypass -File tools\install-cubemx.ps1
```

Скрипт использует механизм автоматической установки IzPack: рядом с
дистрибутивами лежат скрипты `auto-install-<версия>.xml`, поэтому мастер не
задаёт ни одного вопроса. Отдельная версия ставится ключом `-Only 6.4.0`,
другой каталог — ключом `-InstallRoot`.

> **Откуда взялись эти скрипты.** Мастер IzPack на последнем шаге предлагает
> сохранить сценарий выполненной установки. Файлы сняты с реальных установок
> 17.09.2026 и лежат рядом с дистрибутивами — их не нужно составлять заново.
> Попытка написать их по описанию провалилась дважды: у панели `readme`
> обязателен атрибут `id`, а панель ярлыков требует пяти дочерних элементов,
> иначе установка прекращается без сообщений.

> **Без прав администратора установка молча не происходит.** Инсталлятор
> завершается с кодом 1 и ничего не пишет в консоль; при запуске вручную
> показывает окно «Unsufficient rights to install, please try as administrator».
> Проверено 17.09.2026.

Плюс пакет прошивок `STM32Cube_FW_L0_V1.12.x`, который CubeMX скачивает сам —
для офлайн-работы его нужно один раз получить на машине с интернетом и
положить в `%USERPROFILE%\STM32Cube\Repository\`.

**Шаг 5. Прошивка и отладка**

- ST-таргеты: драйвер ST-Link + STM32CubeProgrammer (или встроенный в uVision).
- GD32: официально поддерживается J-Link. В `README.md` репозитория описан
  опыт перепрошивки китайского ST-Link в J-Link — с GD32 он **не заработал**;
  рабочим оказался вариант с отдельным J-Link. В `keil/` остались
  `JLinkLog.txt` и `JLinkSettings.ini` от этих попыток.

### Проверка развёртывания

Окружение считается развёрнутым, когда:

1. `python tools/verify.py` не сообщает о недостающих позициях;
2. `STM32L072CBT6/MDK-ARM/STM32L072CBT6.uvprojx` собирается с 0 ошибок;
3. размер полученной прошивки совпадает с эталонным — **ROM 27.14 КБ**
   (см. [01-overview.md](01-overview.md));
4. прошивка загружается в плату и прибор выводит приветствие на LCD.

Пункт 3 — главный критерий: совпадение размера означает, что собран тот же
код тем же компилятором с теми же ключами.

## Лицензирование

Лицензия на Keil MDK — на стороне владельца проекта, в офлайн-комплект
лицензионные артефакты намеренно не включены.

Полезный факт для оценки вариантов: бесплатная редакция **MDK-Lite ограничена
32 КБ** кода. Текущая прошивка занимает **27.14 КБ**, то есть формально
помещается, но запас всего около 5 КБ — расширение функций по новому ТЗ
вероятно выведет её за лимит. Это аргумент в пользу перехода на GCC,
рассмотренного в [adr/0001-toolchain.md](adr/0001-toolchain.md).
