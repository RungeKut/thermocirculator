# 05. Архитектура прошивки

Актуально на 16.09.2026. Описывает эталонную реализацию на STM32L072CBT6.

## Общее устройство

Прошивка построена на **кооперативном цикле без ОС**. `main()` инициализирует
периферию и уходит в бесконечный цикл, вызывающий единственную функцию:

```c
void UserInterfaceExecuter(void){
    ReadKey();              // опрос кнопок с антидребезгом
    ReadLevel();            // опрос датчиков уровня
    ButtonClickExecuter();  // повторяющиеся действия при удержании
    UpdateScreen();         // обновление экрана и отсчёт времени программы
    RunLineExecuter();      // прокрутка длинных строк
    TempMeasExecuter();     // измерение температуры
    HeaterExecuter();       // ПИД и ШИМ нагревателя
    Sound();                // воспроизведение сигналов
}
```

Каждый исполнитель неблокирующий и сам решает, пора ли ему работать,
сравнивая `HAL_GetTick()` с собственной меткой времени через
`GetTickDifference()`. Прерывания используются только для системного
таймера и завершения преобразования АЦП.

### Модули

| Файл | Ответственность |
|---|---|
| `user_interface.c` | Автомат состояний, экраны, клавиатура, уровень воды, звук |
| `temperature_measurement.c` | Опрос АЦП, таблица NTC, контроль обрыва датчиков |
| `heater_control.c` | ПИД-регулятор и программный ШИМ нагревателя |
| `flash_work.c` | Хранение программ в энергонезависимой памяти |
| `LCD1602.c` | Драйвер дисплея, 4-битный режим |
| `DC_motor_control.c`, `keyboard.c`, `string_display_control.c` | Заглушки, логика фактически живёт в `user_interface.c` |

> Три последних файла пусты (по одной строке). Их содержимое исторически
> переехало в `user_interface.c`. При выделении `app/` их следует либо
> наполнить, либо удалить — см. [08-rules.md](08-rules.md).

## Автомат состояний

Состояние прибора — это пара переменных.

### `stateCurrent` — режим работы

| Значение | Режим | Описание |
|---|---|---|
| `S` | Stop | Останов. Нагрев и моторы выключены, интегратор ПИД сброшен |
| `R` | Run | Работа: моторы включены, ПИД регулирует нагрев |
| `P` | Pause | Пауза: моторы выключены, но ПИД продолжает удерживать температуру |
| `X` | Programming | Режим выбора и правки программ |
| `A` | Alarm | Авария (обрыв датчика температуры) |

### `stateRun` — фаза нагрева

| Значение | Фаза |
|---|---|
| `N` | Нагрев до уставки |
| `S` | Стабилизация: идёт отсчёт времени программы |

### Ключевые переходы

```
Stop ──[Start]──> Run (нагрев)
                    |
                    | currentTemp >= targetTemperature - 5
                    v
                  Pause (stateRun=S, сигнал готовности H)
                    |
                    | [Start] — оператор загрузил продукт
                    v
                  Run (стабилизация, отсчёт времени)
                    |
                    | currentTime <= 3
                    v
                  Stop (сигнал завершения C)
```

Логика в `UpdateScreen()`. Обратите внимание на устройство: **прибор сам
уходит в паузу за 5 °C до уставки** и подаёт сигнал готовности — это момент,
когда оператор загружает продукт. Отсчёт времени программы начинается только
после повторного нажатия Start.

Аварийные переходы:

- срабатывание любого датчика уровня в `R` или `P` → `S`, экран Stop, сигнал `A`;
- обрыв датчика температуры (код АЦП > 4080) → `stateCurrent = A`;
- бездействие оператора в паузе 20 минут → `S`, сигнал `C`.

## Экраны

| № | Экран | Содержимое |
|---|---|---|
| 0 | WAITING | Ожидание (нет воды) |
| 1 | TEMP | Уставка температуры, правится Left/Right |
| 2 | TIME | Уставка времени, правится Left/Right |
| 3 | RUN | Работа: попеременно температура и оставшееся время |
| 4 | PAUSE | Пауза |
| 5 | STOP | Останов |

В режиме программирования — отдельный набор из трёх экранов
(`programScreen`): выбор программы, её температура, её время.

Строки длиннее 8 символов (`StrLength`) прокручиваются автоматически
с интервалом 250 мс, с реверсом на концах и паузой в крайних положениях.

## Тайминги

Сведены в одну таблицу, поскольку разбросаны по коду и легко конфликтуют.

| Что | Период | Где задано |
|---|---|---|
| Антидребезг кнопок | 50 мс | `ReadKey()` |
| Автоповтор при удержании | 200 мс | `ButtonClickExecuter()` |
| Ускорение автоповтора | каждые `speedKeys * 2000` мс, до 30 ступеней | `ReadKey()` |
| Антидребезг датчиков уровня | 5000 мс | `ReadLevel()` |
| Обновление экрана | 3000 мс | `UpdateScreen()` |
| Прокрутка строки | 250 мс | `TimeRunLine` |
| Опрос одного канала АЦП | 200 мс (5 каналов → 1 с на канал) | `TempMeasExecuter()` |
| Пересчёт ПИД | 1000 мс | `HeaterExecuter()` |
| Период ШИМ нагревателя | 1000 мс | `PID_DUTY_CYCLE_MAX` |
| Повтор звукового сигнала | 3000 мс | `Sound()` |
| Таймаут бездействия | 1 200 000 мс (20 мин) | `UpdateScreen()` |

> Отсчёт времени программы привязан к периоду обновления экрана: `currentTime`
> уменьшается на 3 каждые 3000 мс. Это означает, что точность таймера
> программы определяется точностью `HAL_GetTick()`, а не RTC.

## Измерение температуры

Пять каналов опрашиваются по кругу, по одному каждые 200 мс:

| Индекс | Канал | Назначение |
|---|---|---|
| 0 | `ADC_CHANNEL_0` | NTC в ванне № 2 |
| 1 | `ADC_CHANNEL_1` | NTC в ванне № 1 |
| 2 | `ADC_CHANNEL_2` | NTC радиатора |
| 3 | `ADC_CHANNEL_TEMPSENSOR` | Температура кристалла |
| 4 | `ADC_CHANNEL_VREFINT` | Опорное напряжение |

Запуск — `HAL_ADC_Start_IT()`, результат забирается в
`HAL_ADC_ConvCpltCallback()`, обработка — в основном цикле.

Канал выбирается **прямой записью в `ADC1->CHSELR`**, минуя
`HAL_ADC_ConfigChannel()`. Это работает, но создаёт скрытую зависимость:
биты включения внутренних источников (`ADC->CCR`: `TSEN`, `VREFEN`) выставляет
именно `HAL_ADC_ConfigChannel()` при инициализации. Если в CubeMX не
сконфигурированы каналы `TEMPSENSOR` и `VREFINT`, внутренние источники
остаются выключенными — и все измерения обращаются в ноль. Ровно это
произошло с L071, см. [07-troubleshooting.md](07-troubleshooting.md).

Рабочая температура — **максимум** из двух датчиков ванны.

Подробности пересчёта кода АЦП в градусы — [02-hardware.md](02-hardware.md).

## Регулирование нагрева

ПИД с программным ШИМ, период 1 с, пересчёт раз в секунду:

```c
errorCurrent  = currentTemp - targetTemperature;
errorIntegral += errorCurrent;
errorDifferential = errorCurrent - errorPrevious;
pwmDutyCycle = -Kp*errorCurrent - Ki*errorIntegral - Kd*errorDifferential;
// ограничение 0 ... 1000 мс
```

Коэффициенты: `Kp = 100`, `Ki = 1`, `Kd = 500`.

Интегратор сбрасывается при переходе в `Stop` и при входе в паузу в фазе
нагрева.

> **Известная слабость: нет защиты от интегрального насыщения.** Код,
> ограничивающий накопление `errorIntegral` при выходе регулятора на упор,
> присутствует, но закомментирован. При длительном выходе на режим
> интегратор может накопить большое значение и вызвать перерегулирование.
> Кандидат на исправление при переносе в `app/`.

## Хранение программ

16 программ «температура + время» в **последней странице флеш-памяти**:
адрес `0x0801F800`, размер страницы 128 байт, до 32 32-битных значений.

Запись одного значения — цикл «прочитать всю страницу → стереть →
записать обратно с изменением», поскольку флеш допускает только перевод
битов из 1 в 0. Числа `float` хранятся через побитовое преобразование в
`uint32_t` (`FloatToUint` / `UintToFloat`).

> **Не переносится на GD32 как есть.** У GD32E103C8T6 страница 1 КБ, а не
> 128 байт, и всего 64 КБ флеша — адрес `0x0801F800` находится за пределами
> памяти. Модуль подлежит переписыванию, см. [06-porting.md](06-porting.md).

## Замеченные шероховатости

Не ошибки в рабочей прошивке, но места, требующие внимания при переносе:

1. **`GetTickDifference()` дважды вызывает `HAL_GetTick()`** — между вызовами
   значение может измениться, давая разницу на единицу больше или меньше.
   На текущих таймингах безобидно, но правится одной строкой.
2. **`SetSoundFreq()` содержит константу `32000000/f`** — жёсткая привязка к
   тактовой частоте 32 МГц. На GD32 (72 МГц) даст неверную частоту; при
   переносе в `app/` частота тактирования становится параметром порта.
   Нижняя граница 488 Гц, следующая из 16-битного регистра, **сделана
   сознательно**: излучатель ниже ~500 Гц не воспроизводит, и настройки
   таймера подобраны под это. Не дефект.
3. **`Sound()` блокирует основной цикл** цепочками `HAL_Delay()`: сигнал
   завершения и аварийный сигнал останавливают всё на **2.4 секунды**, и в
   это время не идут измерение температуры, пересчёт ПИД, опрос кнопок и
   датчиков уровня. Исправляется по Ф-12 в [09-requirements.md](09-requirements.md).
4. **Скважность ШИМ звука жёстко равна 50 %** — громкость не регулируется.
   См. Ф-11 в [09-requirements.md](09-requirements.md).
5. **Отсутствие anti-windup** в ПИД (см. выше).
6. **Расхождение в именовании кнопок Stop/Left** — см. [02-hardware.md](02-hardware.md).
