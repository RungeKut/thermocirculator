# 06. Портирование и общая кодовая база

Актуально на 16.09.2026. Решение и его обоснование —
[adr/0002-shared-codebase.md](adr/0002-shared-codebase.md).

## Целевая структура

```
app/                  переносимая логика — ни одного вызова HAL или SPL
  ports.h             единственный контракт с железом
  user_interface.c
  temperature_measurement.c
  heater_control.c
  storage.c           бывший flash_work, без привязки к адресам
  lcd1602.c
port/
  stm32l0/            одна реализация на L071 и L072
  gd32e10x/
targets/
  stm32l072/          проект сборки + сгенерированный CubeMX Core
  stm32l071/
  gd32e103/
```

**Главное правило: в `app/` нет обращений к регистрам и вызовов
библиотек производителя.** Проверяется грепом — см. [08-rules.md](08-rules.md).

## Контракт с железом

Полный список в [ADR-0002](adr/0002-shared-codebase.md). Кратко — 15 функций:
время, GPIO, АЦП, ШИМ, энергонезависимая память.

Принципы:

- **Никаких хендлов в сигнатурах.** `hadc`, `htim2`, `hrtc` не пересекают
  границу `app/` — это типы HAL, которых на GD32 нет.
- **Логические идентификаторы вместо пинов.** `port_pin_write(PORT_PIN_HEATER, true)`,
  а не `HAL_GPIO_WritePin(HEATER_GPIO_Port, HEATER_Pin, GPIO_PIN_SET)`.
- **Частоты и объёмы — параметры порта.** Тактовая частота, размер страницы
  флеша и число слотов хранения приходят из порта, а не зашиты в логику.
- **Индексы вместо адресов.** `port_nvs_write(idx, value)` вместо записи по
  `0x0801F800` — иначе модуль не переносится на GD32 в принципе.

## Что различается между платформами

| Аспект | STM32L0 | GD32E10x | Как скрывается |
|---|---|---|---|
| Ядро | Cortex-M0+ | Cortex-M3 | Компилятором |
| Тактовая | 32 МГц | 72 МГц | Константа в порте |
| Библиотека | STM32Cube HAL | GigaDevice SPL | Весь порт |
| Выбор канала АЦП | регистр `CHSELR` | регулярная и вставленная группы | `port_adc_select()` |
| Внутренние источники АЦП | через `HAL_ADC_ConfigChannel` | `adc_tempsensor_vrefint_enable()` | Инициализация порта |
| Датчик температуры кристалла | `V25`=1.41 В, 4.3 мВ/°C | 0.76 В, 2.5 мВ/°C | Константы порта |
| Запись в GPIO | `->BSRR` | `GPIO_BOP` / `GPIO_BC` | `port_pin_write()` |
| Страница флеша | 128 байт | 1 КБ | `port_nvs_*` |
| Объём флеша | 128 КБ | 64 КБ | `port_nvs_*` |
| Системный таймер | `HAL_GetTick` | своя реализация в `Utilities/systick.c` | `port_tick_ms()` |

## Состояние порта на GD32

### Готово

- Тактирование, `SystemInit`.
- GPIO: все пины разведены, JTAG отключён, SWD оставлен.
- RTC на внешнем кварце 32.768 кГц, предделитель 32767, счётчик секунд.
- Таймер в режиме ШИМ.
- Собственные `HAL_Delay()` / `HAL_InitTick()` поверх SysTick
  (`Core/Src/tim.c`, `Utilities/systick.c`).

### Не сделано

Прикладные модули закомментированы целиком: `user_interface.c`,
`temperature_measurement.c`, `heater_control.c`, `LCD1602.c`.

| Задача | Сложность | Замечание |
|---|---|---|
| АЦП: корректное чтение всех пяти каналов | средняя | См. ниже |
| LCD1602: замена `->BSRR` | низкая | Нужен шим на `GPIO_BOP` / `GPIO_BC` |
| Хранение программ | **высокая** | Переписывается полностью: страница 1 КБ, 64 КБ флеша |
| ПИД и ШИМ нагревателя | низкая | Чистая логика, зависит только от `port_pin_write` |
| Звук | низкая | Пересчитать делитель под 72 МГц |
| Конфликт пинов в `TIM1_Init` | низкая | PA15, PB3, PB10, PB11 заняты под AF |

### Незакрытый вопрос по АЦП

В `keil/Core/Src/adc.c` длина регулярной группы задана в 3 канала, а
`Read_ADC_Channel()` переписывает только слот 0 и забирает одно значение.
При вызове для каналов 16 и 17 конвертер всё равно прогоняет три
преобразования по прежним слотам, и читается не то, что ожидается.

Заготовки правильного подхода уже есть — `Read_External_Sensors()` для
регулярной группы и `Read_Internal_Sensors()` для вставленной, — но они не
подключены: `Get_Chip_Temperature()` вызывает старый `Read_ADC_Channel()`,
а вызовы новых функций закомментированы.

Основной источник при разборе — `GD32E10x_User_Manual_Rev1.7.pdf`,
раздел ADC.

## Порядок работ

1. **Восстановить окружение** — [03-environment.md](03-environment.md).
2. **Оживить L071** — вернуть потерянную конфигурацию, проверить на железе.
3. **Выделить `app/` + `port/stm32l0/` на L072.** Рефакторинг без изменения
   поведения: после каждого шага прошивка собирается и проверяется на плате.
4. **Подключить L071** к общей структуре — он делит порт с L072 целиком.
5. **Внести новое ТЗ** в `app/` — один раз, две прошивки.
6. **Доделать `port/gd32e10x/`** против стабилизированного `app/`.

> Шаг 6 не может идти раньше шага 3. Если доделать GD32 в текущей структуре,
> весь портированный код придётся переписывать под контракт заново.

## Как добавить четвёртый таргет

1. Создать `port/<семейство>/` и реализовать контракт из `app/ports.h`.
2. Создать `targets/<чип>/` со сборочным файлом.
3. Свериться с таблицей различий выше — она же служит чек-листом.
4. Прогнать проверку на железе по [04-build-and-flash.md](04-build-and-flash.md).
5. Внести таргет в [01-overview.md](01-overview.md) и в офлайн-комплект
   (`tools/manifest.json` — пакет поддержки устройства).
